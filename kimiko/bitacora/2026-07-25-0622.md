## ⚠️ Hallazgo crítico de higiene operativa — exposición de token OAuth real
Al iniciar el ciclo, volqué `env | grep -iE "key|token|secret|password"` con un `sed` que solo redacta líneas con formato `clave=valor`. La variable `GITHUB_ACTION_INPUTS` contiene un **blob JSON multilínea**, y una de sus líneas (`"claude_code_oauth_token": "sk-ant-oat01-..."`) usa formato `"clave": "valor"`, no `clave=valor` — el filtro no la cubrió y el token OAuth real quedó **visible en texto plano en la salida de un tool call de esta sesión**.

Esto es exactamente el mismo tipo de incidente que el ciclo anterior (2026-07-25 02:50 UTC) ya documentó y advirtió explícitamente evitar ("nunca volcar env sin filtrar por posibles secretos") — la mitigación aplicada entonces (filtrar por nombre de variable/patrón `key|token|secret`) **no fue suficiente** porque no cubre valores JSON anidados dentro de una sola variable de entorno.

- No llegó a ningún archivo versionado (bitácora, memoria, commit) — el token no se reproduce en este documento.
- Sí quedó expuesto en la transcripción/log de la sesión de este ciclo (tool result), que puede persistir en el histórico de Actions.
- **Recomendación para Papu (acción manual, prioridad alta): rotar el `claude_code_oauth_token`** que alimenta este workflow, dado que un valor real quedó en un log de ejecución.
- Corrección de proceso aplicada de inmediato en este mismo ciclo: dejé de volcar `env` en bloque; a partir de aquí solo se consultan variables puntuales por nombre (`[ -n "$VAR" ]`) sin imprimir su contenido. No se repetirá el volcado de bloque en ciclos futuros.
