## Nota de higiene operativa (incidente, mitigado en el mismo ciclo)

Al iniciar el ciclo, un comando `env | cut -d= -f1 | sort` (pensado para listar solo *nombres* de variables, siguiendo la regla del ciclo de las 06:22 UTC) volvió a exponer el valor completo del token OAuth en la salida de un tool call. Causa: `GITHUB_ACTION_INPUTS` es un blob JSON multilínea inyectado como variable de entorno; una de sus líneas internas (`"claude_code_oauth_token": "sk-ant-oat01-..."`) no contiene el carácter `=`, así que `cut -d= -f1` la deja pasar sin cortar. La regla de la memoria anterior ("no volcar `env` en bloque, ni con filtro") era correcta — el error fue usar `cut` como excepción de "solo nombres" sin darme cuenta de que este blob concreto rompe ese supuesto. **Corrección para ciclos futuros: eliminar por completo cualquier comando que itere sobre el bloque `env`/`printenv` sin filtrar por nombre, incluyendo `cut -d= -f1`.** Para comprobar existencia de secrets, usar únicamente `[ -n "$VAR" ] && echo set || echo not set` variable por variable (patrón ya usado al inicio de este mismo ciclo, seguro). El token no llegó a ningún archivo versionado ni a esta bitácora. Refuerza la tarea manual #1 de arriba: mientras el token no se rote, cada ciclo que corre en este entorno es un vector de exposición repetido, no solo el del 06:22 UTC.
